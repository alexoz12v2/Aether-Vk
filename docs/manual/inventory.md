## Gaps found while reading (fix in the app, or capture by name)

- Expanders without an AutomationId: *Comet Selection* (Comet tab), *Custom mesh* (Settings ›
  Comet Appearance), the per-billboard expander (Settings › Billboards), the three *Step N*
  expanders of `HorizonJplView`. `ParticleRenderingSection` and `InputBindingsSection` only
  have `x:Name`. Avalonia uses `x:Name` as the automation id when none is set. The e2e suite
  already relies on this: `ReviewSave.SetQuality` expands `ParticleRenderingSection`, and
  `ThesisScenarioTests` clicks `ViewportHost`.
- The Comet tab's commit block (`ReferenceOrbitPicker`, `DownloadCommitButton`,
  `DownloadStatusText`) is not inside an expander. Crop it with the union of those three
  element rectangles.
- No ids at all: `SettingsWindow`, `ManageImportsWindow`, `SpawnImageDialogWindow`,
  `FatalErrorWindow`, `SplashWindow`, `ConsoleView`. Capture these as whole windows by title.
- The Snap-above buttons (*Sun*, *Comet*, *Earth*) in Settings › Viewport (Orbit mode) and
  *Move observer there* have no AutomationId. Find them by name inside
  `ViewportSettingsSection`.
- Labels shown as `?` are bound to computed view-model properties (epoch labels, status
  texts), not to `Str*` strings. Read them from a live capture (`TreeDumpTests`).
- `ItemsControl` templates (billboard rows, viewport sections, jets, FITS fields) appear once
  here. At run time there is one per item.
